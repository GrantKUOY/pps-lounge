# PPS Aviation Journal 視覺與工具化設計規格

日期：2026-07-01

狀態：已由 Grant 核准設計方向，待書面規格審閱

目標分支：`redesign-v2`

正式網站：`https://pps-lounge.vercel.app/`

## 1. 背景

PPS Lounge v2 已完成手機優先搜尋、篩選、詳情、CSV 匯出與 120ms 搜尋 debounce，但目前視覺仍具有常見 AI／Codex 範本特徵：巨型置中 Hero、灰白 Apple 式配色、膠囊按鈕、圓角卡片與卡片內再分資訊方塊。這些元素可用但缺乏 PPS Lounge 專屬辨識度。

正式舊版另有每次輸入即完整重建篩選器的效能問題；新版架構已將篩選器初始化與搜尋結果渲染分離。相同量測下，新版在 6 倍 CPU 降速時約 128–159ms 完成可見更新，快速輸入 `T → TP → TPE` 只渲染一次。

## 2. 設計目標

將新版塑造成「航空編輯誌 × 可靠搜尋工具」：

- 具備高級旅行指南的編輯判斷、排版質感與專屬語彙。
- 旅客進站後能立即搜尋，不必先瀏覽品牌行銷封面。
- 以機場代碼、航廈、位置、營業時間與權益條件形成視覺結構。
- 不依賴照片建立高級感，避免圖片授權、品質與維護負擔。
- 保留新版既有搜尋效能、無障礙與響應式能力。
- 讓後續 Codex、Claude 或其他 AI 都能依同一份規範維持品牌一致性。

## 3. 非目標

- 不在本輪設計或實作自動抓取後端。
- 不加入貴賓室、機場或目的地照片。
- 不重新設計正式舊版。
- 不改變 Priority Pass 權益規則或推測官方未提供的資料。
- 不在完成驗證與 Grant 另行核准前部署 Production。
- 不將 `redesign-v2` 合併至 `main`。

## 4. 核准決策

| 項目 | 決策 |
|---|---|
| 品牌方向 | 高級旅行指南 |
| 視覺概念 | 航空編輯誌（Aviation Journal） |
| 圖片策略 | 無照片 |
| 首頁配置 | 搜尋優先 |
| Hero 行為 | 保留最多兩行品牌序言，不使用巨型封面或自動收合動畫 |
| 結果呈現 | 編輯式清單，不使用卡片牆 |
| 詳情呈現 | 可掃讀的資料版面，不使用多層卡片或資訊方塊 |
| 主要裝飾語彙 | 機場代碼、航廈標示、細分隔線、紙張色與編輯式排版 |

## 5. 品牌命題

> 像一本懂機場的旅行刊物，也像一件可靠的隨身工具。

高級感來自資訊節制、文字品質、精確對齊與安靜的視覺節奏，不來自大量留白、裝飾動畫、陰影或將內容包成卡片。

「編輯誌」不代表製造虛構期號、假引言或與資料無關的裝飾。所有結構元素必須表達真實資訊，例如機場代碼、航廈、據點類型、資料日期或結果數量。

## 6. 視覺基礎

### 6.1 色彩 tokens

| Token | 色值 | 用途 |
|---|---|---|
| `--paper` | `#F3EFE5` | 主畫布，形成溫暖紙張感 |
| `--paper-raised` | `#FAF7EF` | 必須區分層級時使用，不作卡片牆 |
| `--ink` | `#202522` | 主文字、主要線條 |
| `--ink-muted` | `#65645E` | 次要資料與說明 |
| `--oxblood` | `#8F2639` | 互動、重要分類與焦點 |
| `--rule` | `#B8B0A1` | 分隔線 |
| `--error` | `#A32D24` | 錯誤狀態 |
| `--success` | `#35624A` | 成功或可用狀態；不得大量鋪色 |

規則：

- 酒紅是唯一品牌互動色，不沿用 Apple Action Blue。
- 不使用裝飾漸層、玻璃擬態或發光效果。
- 陰影只允許在需要表達原生浮層的 dialog／bottom sheet 使用，而且必須低對比。
- 正文與互動狀態必須符合 WCAG 2.2 AA 對比要求。

### 6.2 字體角色

- 顯示字與場所名稱：`Noto Serif TC`、`Source Han Serif TC` 或可用的繁體中文襯線字，後備 `Georgia, serif`。
- 操作、數字、資料與正文：`Noto Sans TC`、系統無襯線字。
- 機場代碼：無襯線粗體，採緊字距，作為導航資訊而非裝飾 Logo。
- 襯線字不得用於按鈕、篩選欄位、長條件文字或密集資料。
- 正式上線不得依賴未授權的商業字型；若載入網路字型，必須有明確授權、字型子集與 fallback。

### 6.3 形狀與層級

- 一般內容區塊不使用陰影。
- 結果列使用細線分隔，不放入獨立圓角卡片。
- 一般圓角上限 4px；原生浮層與搜尋輸入可依可用性使用 8–12px。
- 膠囊形只允許表達真正的可切換篩選狀態；不得把每個設施都做成彩色膠囊。
- 資訊層級主要依靠字級、粗細、間距與細線，不靠多層背景盒。

## 7. 工具化資訊架構

「工具化」指的是介面先服務旅途中正在完成的任務，再用編輯式設計提高品質，而不是把功能包裝成行銷頁。

### 7.1 首頁首屏

依序包含：

1. 高度精簡的 PPS Journal masthead。
2. 最多兩行的品牌序言。
3. 主要搜尋輸入。
4. 最近搜尋或搜尋提示。
5. 搜尋後的機場摘要與第一筆結果。

390 × 844px 裝置在輸入查詢後，首屏必須看得到第一筆結果的名稱與核心資料。

### 7.2 搜尋

- 保留 120ms debounce。
- 快速連續輸入只執行最後一次搜尋。
- 有效三碼機場代碼以精確機場結果優先，不得匹配一般英文單字子字串。
- 搜尋框在向下瀏覽後可縮為 sticky 工具列，但不得用自動收合動畫造成版面跳動。
- 建議項目只顯示機場代碼、機場／城市名稱及結果數量。

### 7.3 搜尋結果

結果頂部顯示：

- 大型機場代碼。
- 機場名稱。
- 結果總數、航廈數與類型數。
- `全部／貴賓室／餐飲` 快速切換及進階篩選入口。

每列結果至少顯示：

- 航廈與據點類型。
- 據點名稱。
- 當日或一般營業時間摘要。
- 位置摘要。
- 最多三項重要設施或權益。
- 明確的「查看詳情」操作。

不得在清單中完整顯示長條件文字。不得將每項資料放入獨立資訊方塊。

### 7.4 篩選

- 首層只保留 `全部／貴賓室／餐飲`。
- 國家、城市、設施、排序與每頁筆數放入進階篩選 bottom sheet／dialog。
- 開啟浮層後焦點必須正確移入，關閉後返回觸發按鈕。
- 篩選器選項只在資料初始化或相關篩選條件改變時更新；關鍵字輸入不得重建全部選項。

### 7.5 詳情

詳情依序呈現：

1. 返回該機場結果。
2. 機場代碼、場所名稱、機場與航廈。
3. 位置。
4. 營業時間。
5. 設施。
6. 使用條件。
7. Priority Pass 官方連結。
8. 資料可能變動的提醒。

手機可使用全高 dialog 或獨立頁面語意；視覺上不得使用卡片套卡片。長原文以可展開區塊呈現。

## 8. 狀態與錯誤處理

- 載入中：使用文字與細線骨架，不使用閃爍漸層。
- 無結果：保留目前查詢內容，提供清除與修改搜尋的明確操作。
- 資料載入失敗：說明資料目前無法取得，提供重試，不顯示虛構結果。
- 官方網址缺漏：不顯示失效按鈕，改為文字說明。
- 外部網址：只允許安全 HTTPS URL，並以新分頁開啟。
- `localStorage` 不可用：最近搜尋無害降級，不影響主要搜尋。

## 9. 響應式與無障礙

- 驗證寬度：320、375、390、768、1024px。
- 可見按鈕、輸入與 select 觸控高度至少 44px。
- 不得出現水平溢出。
- 支援鍵盤完成搜尋、篩選、詳情與返回流程。
- 使用語意 HTML，動態結果數量以適當 `aria-live` 回報。
- 焦點樣式使用酒紅與可辨識外框，不只依賴顏色。
- 支援 `prefers-reduced-motion`；核心操作不依賴動畫理解。

## 10. 效能預算

- 120ms debounce 保持不變，除非量測證明需要調整。
- 6 倍 CPU 降速、390 × 844px 條件下，關鍵字輸入至結果可見須小於 250ms。
- 快速輸入 `T → TP → TPE` 只允許一次結果渲染。
- 關鍵字搜尋不得重新建立國家、城市、類型或設施選項。
- 首屏不新增外部圖片、影片或阻塞式第三方字型。
- 瀏覽器 console 不得有未處理錯誤。

## 11. 資料前置條件

目前 `redesign-v2` 為 1,755 筆資料，仍保留舊 TPE 7 筆基準；正式舊版 hotfix 後為 1,754 筆，包含 KEF Elda、移除 TPE `Plaza Premium Lounge (Zone A)`，並更新其餘 6 筆 TPE 官方網址。

新版發布前必須：

- 同步正式 hotfix 的 KEF／TPE 資料。
- 驗證 TPE 精確結果為 6 筆。
- 驗證 KEF 同時包含 Jomfruin 與 Elda。
- 驗證所有 TPE 與 Elda 官方網址回應正常。

這是發布前資料同步，不等同於實作自動抓取後端；自動資料後端維持獨立規劃。

## 12. DESIGN.md 與技能治理

實作階段應在 repo 根目錄建立 `DESIGN.md`，內容以本規格為唯一來源，並將外部 Apple `DESIGN.md` 降為歷史參考，不再作為主規範。

技能優先順序：

1. 專案 `DESIGN.md`：品牌與元件決策的最高視覺依據。
2. `frontend-design`：依專案規格產生具有辨識度的實作。
3. `web-design-guidelines`：檢查互動、響應式與通用網頁品質。
4. 現有 `clean`：只檢查可讀性、狀態與無障礙；不得帶入其預設字型或藍紫配色。
5. Playwright、Lighthouse 與效能量測：提供可重現驗證。

推薦安裝：

```bash
npx skills add https://github.com/anthropics/skills --skill frontend-design
npx skills add https://github.com/vercel-labs/agent-skills --skill web-design-guidelines
```

不得讓任何 skill 的預設 tokens、字型、配色或元件樣式覆蓋專案 `DESIGN.md`。

## 13. 驗證與驗收

### 自動驗證

- 既有 unit tests 全數通過。
- 既有 Playwright tests 全數通過。
- 新增快速連續輸入只渲染一次的效能回歸測試。
- 新增 TPE 6 筆與 KEF 兩筆餐飲資料回歸測試。
- 新增 390 × 844px 搜尋後首屏可見第一筆結果的檢查。
- 執行 HTML 跳脫、安全 URL、錯誤狀態與 `localStorage` 降級測試。

### 視覺驗證

- 320、375、390、768、1024px 保存截圖。
- 搜尋前、搜尋結果、無結果、篩選、詳情、錯誤狀態均需檢查。
- 禁止模式檢查：巨型 Hero、Apple 藍、裝飾漸層、卡片牆、卡片套卡片、膠囊海及非必要陰影均不得出現。
- Grant 使用實體 iPhone Safari 完成搜尋、篩選與詳情流程。

### 發布 Gate

- `redesign-v2` 完成自動與人工驗證。
- Grant 明確核准 push／Preview／Production。
- 未取得核准前，不合併 `main`、不切換 Vercel Production。

## 14. 風險與緩解

| 風險 | 緩解 |
|---|---|
| 編輯式排版降低資料可掃讀性 | 襯線字只用於標題；操作與資料維持無襯線 |
| 無照片後視覺過於平淡 | 以機場代碼、比例、細線、紙張色與真實資料形成結構 |
| 酒紅互動色對比不足 | 實作時逐一量測 AA 對比並提供清楚焦點外框 |
| 高級感導致過多留白 | 以首屏結果可見與 390 × 844px 驗收限制密度 |
| skill 帶入自身風格 | 專案 `DESIGN.md` 優先，禁止覆蓋 tokens 與字型 |
| 視覺重構影響搜尋效能 | 保留搜尋模組並加入 6 倍 CPU 降速效能預算 |
| 新版資料落後正式 hotfix | 發布前執行 KEF／TPE 資料同步與回歸測試 |

## 15. 實作邊界

本規格核准後，下一步只建立詳細實作計畫，不直接開始修改 UI。實作計畫必須拆分為：

1. 建立 repo `DESIGN.md` 與設計 tokens。
2. 同步正式 KEF／TPE 資料。
3. 首頁與搜尋工具列重構。
4. 結果清單與篩選重構。
5. 詳情與狀態頁重構。
6. 響應式、無障礙與效能驗證。
7. iPhone Safari 人工驗收與發布 Gate。
